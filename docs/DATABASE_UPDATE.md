# 2026-10-27 판매 설정 DB 변경 안내

## 적용 상태 (2026-10-28)

사용자 정정: 개발용은 로컬 앱 실행을 의미하며 별도 DB 분리는 필요 없다. 배포하지 않는다.
기존 `.env`의 Neon DB에 추가 SQL 적용 완료. 기존 데이터 삭제 없이 `StoreSettings`와 `Order.shippingFee`를 추가했다.
로컬 실행기는 `.env`를 사용하며 `.env.development.local`은 필수가 아니다. 사용자가 만든 파일은 그대로 보존한다.

## 로컬 검증 명령

```powershell
node scripts/development.mjs check
npm run db:apply:dev
npm test
npm run test:integration
npm run build:dev
npm run start:dev
```

`dev`라는 명령 이름은 로컬 실행을 뜻한다. `DATABASE_URL`은 `.env`에 지정한 Neon DB이다.
통합 테스트는 이 실행에서 만든 사용자/상품/주문/설정만 정리하며 기존 고객과 공유 상점 설정은 변경하지 않는다.
Netlify 배포 및 Git push는 수행하지 않는다.

## 변경 내용

- `StoreSettings`: 상점 공개 설정 JSON, 버전, 수정 시각. 기본 행은 관리자가 처음 저장할 때 생성.
- `Order.shippingFee`: 정수, 기본값 0. 기존 무료배송 주문의 금액은 그대로 유지.
- 기존 테이블/컬럼/주문 데이터 삭제 없음.
- 설정 저장 시 AdminActionLog에 수정자와 버전 기록. 계좌/정책 전문은 감사 로그에 복제하지 않음.

## 승인 후 적용 순서

1. 대상 DB가 개발/스테이징/운영 중 무엇인지 확인하고 제공자의 백업/복구 지점을 확보한다.
2. 운영이라면 주문 쓰기를 잠시 중단하는 점검 시간에 수행한다. 컬럼 추가는 테이블 잠금을 획득할 수 있다.
3. 프로젝트 루트에서 대상 `DATABASE_URL`을 확인한 환경으로 다음 명령을 실행한다. 자격증명은 출력하거나 커밋하지 않는다.

```powershell
npx prisma db execute --file prisma/patches/20261027_store_settings.sql --schema prisma/schema.prisma
npm run db:generate
npm run build
```

4. DB 변경 성공 후 앱을 배포한다. 앱 배포는 별도 승인 대상이다.
5. 관리자로 설정 저장→다시 조회→비로그인 홈/고객 안내 반영을 확인한다.
6. 격리된 테스트 DB에서 배송비 0/유료 주문, 기존 주문 금액 보존, 동일 요청 키 재시도, 동시 취소·만료를 검증한다.

## 되돌리기

앱을 이전 버전으로 되돌리더라도 추가 컬럼/테이블은 유지할 수 있다. 데이터 삭제를 수반하는 다운 SQL은 제공하지 않는다.
유료 배송 주문이 생성된 이후에는 이전 앱이 배송비를 무료로 표시할 수 있으므로 무조건 이전 앱으로 복귀하지 말고 주문 화면 호환성을 먼저 확인한다.

## 주문 재시도 계약

웹 장바구니는 `Idempotency-Key`를 생성하고 같은 내용의 재시도에 재사용한다.
서버는 사용자 ID와 요청 키의 SHA-256으로 주문 PK를 만들며 같은 키의 주문을 한 번만 생성한다.
이미 저장된 주문과 상품/수량/수령정보/입금자명이 다르면 409를 반환한다.
기존 API 호출 호환성을 위해 키가 없는 요청도 허용하지만 해당 호출은 중복 방지 대상이 아니다.
재시도 시 배송지가 삭제되었거나 기본배송지/회원명이 바뀌면 소유권/내용 검증에 실패할 수 있다. 이때 기존 주문 내역을 먼저 확인한다.

## 테스트 범위

회귀 테스트는 실제 API 핸들러와 메모리 DB 대체물을 사용한다. PostgreSQL 잠금/트랜잭션 동작 자체를 검증한 통합 테스트는 아니다.
실제 OAuth·인증된 관리자 화면 저장 검증은 별도로 필요하다. PostgreSQL 통합 테스트 결과는 아래 실행 기록에 남긴다.
