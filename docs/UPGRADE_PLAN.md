# 오늘의귤 고도화 작업 계획

기준일: 2026-10-27. 현재 Next.js/Prisma 구조를 유지하고 아래 순서로 진행한다.
운영 배포·운영 DB 변경·외부 알림 발송은 별도 승인 후 실행한다.

| 순서 | 작업 | 주요 파일/영역 | 완료 기준 |
|---|---|---|---|
| 1 | 주문 상태와 재고 정합성 | `src/app/api/orders`, `src/app/api/admin/orders`, 상태 전이 공통 함수 | 동시 취소·만료·입금요청 중 한 전이만 성공; 재고는 한 번만 복구; 확인 대기 주문은 만료 제외 |
| 2 | 인증·관리 권한 강화 | `src/auth.ts`, 관리자 API/페이지 | 외부 리다이렉트 차단; 회수된 관리자 권한으로 조회·변경 불가 |
| 3 | 주문 재시도와 입력 검증 | 주문 API, 장바구니 | 같은 요청 키 재시도로 주문/재고 중복 생성 방지; 잘못된 입력은 400 반환 |
| 4 | 매출·주문 기록 정확성 | 매출 페이지, 주문 상세 | 한국 월 경계 정확; 장애를 0원으로 숨기지 않음; 저장된 입금 계좌 사용 |
| 5 | 구매 흐름 복원 | 로그인, 미들웨어, 상품 버튼, 프로필 설정, 장바구니 | 로그인 후 상품 복귀; 탐색 중 배송지 강제 입력 제거; 주문 시 배송지 입력 후 장바구니 복귀; 품절 구분 |
| 6 | 판매 콘텐츠와 고객 안내 | 홈, 메타데이터, 고객센터/정책 | 실제 농장 정보·연락처·배송/보상 기준 확인 후 반영; 빈 링크 제거 |
| 7 | 사진·상품 규격 | 상품 폼/API, 이미지 저장소, Prisma | 저장소 선정 후 업로드/검증/삭제 수명 관리; 중량·등급·옵션별 재고; 실사진 적용 |
| 8 | 출고·고객 대응 | 관리자 주문, 알림 연동, 환불 기록 | 출고 목록/송장 일괄 처리/환불 이력; 외부 서비스 선정 후 알림 연동 |
| 9 | 판매 개선 측정 | 구매 단계 이벤트, 재구매 | 수집 범위·개인정보 정책 확정 후 전환·이탈 측정; 시즌 재구매 지원 |

## 검증

- 회귀 테스트: 주문 상태 충돌, 재고 복구, 재시도, 악성 복귀 URL, 월말/연말 한국 시간 경계.
- 정적 검사: 타입 검사, 린트, 프로덕션 빌드.
- 실제 DB 동시성·OAuth·모바일 결제 흐름: 운영 데이터와 분리된 환경에서 후속 검증.
- DB 스키마 변경이 필요한 상품 옵션/스냅샷 확장은 마이그레이션과 기존 데이터 호환 계획을 먼저 준비한다.

## 확인이 필요한 정보

실제 농장명/지역/연락처, 인증·농장 이력, 배송비/출고 기준, 파손·부패 접수/보상 기준,
실제 사진, 이미지 저장소 및 알림 서비스. 미확인 정보를 임의로 작성하지 않는다.

## 진행 기록

- 1~5: 코드 구현 완료. 상태 충돌/재시도/권한/월 경계 회귀 테스트, 타입·린트·빌드 검증 수행.
- 6: 사용자 요청에 따라 `/admin/settings`에서 직접 수정하는 방식으로 구현. GAP 기본 숨김, 농장/연락처/계좌/배송비/출고/파손/약관 편집, 공개 홈·고객 안내 연결.
- 설정 저장에는 `StoreSettings` 테이블과 `Order.shippingFee` 컬럼이 필요하다. 2026-10-28 사용자 정정에 따라 기존 .env의 Neon DB에 추가 SQL 적용 완료. 로컬 검증만 진행하며 배포하지 않음.
- 7~9: 후속 작업. 사진 저장소/옵션 정책/알림 서비스/측정 범위를 정한 후 구현한다. 현재 작업 완료로 표시하지 않는다.
- DB 연결 없이 수행하는 테스트는 실제 핸들러+메모리 대체물이다. PostgreSQL 동시성 및 OAuth 전체 흐름은 격리된 환경에서 추가 검증 필요.
